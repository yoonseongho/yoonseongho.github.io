운송관리시스템(TMS) 고도화

2024.01 ~ 2025.01 · 1년

Vue.js 기반 물류 관리 화면 개발 · 대용량 데이터 조회 및 실적 집계 개선

프로젝트 개요

보세·항공·내륙 운송 업무를 지원하는 운송관리시스템을 고도화했습니다. 기준정보 관리부터 배차 현황, 월간 운송 실적 및 컨테이너별 손익 조회까지 물류 업무에 필요한 프론트엔드 화면을 개발했습니다.

기술 스택

Vue.js JavaScript Java Spring Boot REST API MyBatis PostgreSQL

담당 업무

  • 운임·선사·차량·기사·샤시 등 기준정보 관리 화면 개발
  • 일자·부서·협력사별 가용 차량 및 배차 현황 조회 구현
  • 월간 운송 실적 및 컨테이너별 매출·비용 조회 화면 개발
  • Server-side Pagination을 활용한 대용량 목록 조회 처리
  • REST API 연동 및 SQL 조회·집계 로직 개선

주요 구현 기능

1. 기준정보 관리 및 대용량 데이터 조회

운송 업무에 필요한 마스터 데이터를 관리하고, 페이지 단위 조회를 통해 대량 데이터의 화면 처리 부담을 줄였습니다.

  • 차량 14,722건 및 기사 5,014건 대상 Server-side Pagination 적용
  • 운임·선사 코드 등 기준정보 조회 및 관리 기능 구현
  • 차량·샤시 정보와 Location/Depot 매핑 화면 개발

2. 운송 실적 및 손익 조회

운송료·부가·부대 항목별 실적과 컨테이너별 청구 금액 및 비용을 조회할 수 있는 업무 화면을 개발했습니다.

  • 월간 운송 실적 및 비용 집계 화면 구현
  • W/O No. 및 CNTR No. 기준 컨테이너 실적 조회
  • I/O 구분 및 철송 여부 등 조건별 데이터 조회

트러블 슈팅

1. 대용량 데이터 조회 성능 개선

문제

차량·기사 데이터 조회 시 다중 JOIN으로 SQL 실행이 지연되고, 대량의 조회 결과로 인해 화면 처리 부담이 발생했습니다.

해결

  • 조회 조건에 사용되는 컬럼의 인덱스 검토 및 복합 인덱스 적용
  • 불필요한 Inline View를 정리해 SQL 조회 구조 개선
  • PostgreSQL LIMIT/OFFSET 기반 Server-side Pagination 적용

결과

페이지 단위로 데이터를 조회하도록 개선해 초기 로딩과 대용량 목록 화면의 처리 부담을 완화했습니다.

2. 실적 집계 소계·합계 불일치 해결

문제

특정 W/O 조건에서 금액 항목의 NULL 처리로 인해 Pivot 집계 결과의 소계와 합계가 일치하지 않았습니다.

해결

  • COALESCE를 적용해 NULL 값 처리 기준 통일
  • CASE-WHEN 기반 Pivot 집계 조건 검토 및 수정
  • 다양한 W/O 조건의 집계 결과 검증

결과

금액 집계 오류를 수정해 월간 운송 실적과 컨테이너별 손익 데이터의 일관성을 개선했습니다.

프로젝트 성과

  • 대용량 차량·기사 데이터에 페이지 단위 조회 구조 적용
  • 운송 실적 및 컨테이너별 손익 데이터 조회 화면 구현
  • SQL 조회 구조 개선을 통한 데이터 조회 부담 완화
  • NULL 처리 및 Pivot 집계 조건 개선으로 실적 데이터 정합성 향상
