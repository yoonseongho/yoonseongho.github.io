운송관리시스템(TMS) 고도화

2024.01 ~ 2025.01 · 1년

보세·항공·내륙 운송 업무를 지원하는 운송관리시스템을 고도화한 프로젝트입니다. Vue.js 기반의 기준정보 관리 및 실적 조회 화면을 개발하고, 대용량 데이터 페이징과 운송 실적 시각화, 조회 데이터 정합성 개선을 통해 사용자가 물류 데이터를 효율적으로 확인하고 관리할 수 있도록 지원했습니다.

Frontend Vue.js · JavaScript
Data Handling Server-side Pagination
Domain TMS · 물류 데이터

프로젝트 개요

운송 업무에 필요한 기준정보부터 배차 현황, 월간 실적 및 컨테이너별 손익까지 다양한 물류 데이터를 조회하고 관리할 수 있는 업무 시스템입니다.

01

기준정보 관리

운임, 선사, 차량, 기사, 샤시 및 Location/Depot 등 운송 업무에 필요한 마스터 데이터의 조회와 관리

02

운송 현황 조회

일자·부서·협력사별 가용 차량 현황 및 배차 관련 데이터 조회 기능

03

실적 및 손익 분석

월간 운송 실적과 컨테이너별 매출·비용 데이터를 비교하고 분석할 수 있는 조회 화면

기술 스택

프론트엔드 화면 개발부터 API 연계 및 데이터 조회 처리까지 프로젝트에서 활용한 기술입니다.

Frontend

Vue.js JavaScript HTML / CSS

Backend & Database

Java Spring Boot REST API MyBatis PostgreSQL

  • 검색 조건 및 데이터 조회 기능 구현

    업무별 조회 조건을 적용하고, 운송 및 배차 현황을 확인할 수 있는 화면을 구현했습니다.

  • 대용량 목록 조회 및 페이징 처리

  • 실적 분석 화면 개발

    관리 화면에서 사용하는 데이터의 요청·조회·표시 흐름을 점검하고 관련 API 및 SQL 처리 로직을 개선했습니다.

트러블 슈팅

ISSUE 01 · PERFORMANCE

대용량 차량·기사 데이터 조회 성능 개선

문제 상황

차량 및 기사 데이터를 조회할 때 다중 JOIN으로 인한 쿼리 실행 지연이 발생하고, 조회 결과가 많아질수록 프론트엔드 목록 화면에서 처리해야 할 데이터가 증가했습니다.

원인 분석

  • 다중 JOIN을 포함한 조회 쿼리의 실행 부담
  • 많은 데이터를 한 번에 전달하고 화면에서 처리할 때 발생하는 렌더링 부담

해결 과정

  • 조회 조건에 사용되는 컬럼의 인덱스를 검토하고 복합 인덱스 적용
  • 불필요한 Inline View를 정리하고 SQL 조회 구조 개선
  • PostgreSQL의 LIMIT/OFFSET 기반 Server-side Pagination을 적용해 필요한 데이터를 페이지 단위로 조회하도록 변경

개선 결과

한 번에 조회하고 화면에 전달하는 데이터 양을 줄여 초기 로딩 부담을 완화하고 대용량 기준정보 목록의 조회 효율을 개선했습니다.

ISSUE 02 · DATA CONSISTENCY

월간 실적 집계의 소계·합계 불일치 해결

문제 상황

특정 W/O 조건에서 일부 금액 항목이 NULL로 계산되면서 Pivot 집계 결과의 소계와 합계가 일치하지 않는 문제가 발생했습니다.

원인 분석

  • 금액 집계 과정에서 NULL 값에 대한 처리 기준이 일관되지 않음
  • CASE-WHEN 기반 Pivot 조건에 따른 집계 결과 점검 필요

해결 과정

  • SQL 집계식에 COALESCE를 적용해 NULL 값 처리 기준 통일
  • CASE-WHEN 기반 Pivot 연산 조건을 검토하고 집계 로직 개선
  • 다양한 W/O 조건과 금액 조합을 기준으로 결과 검증

개선 결과

NULL 값으로 인해 발생하던 집계 오차를 수정하고, 월간 운송 실적 및 컨테이너별 손익 데이터의 일관성을 개선했습니다.

프로젝트 성과 및 배운 점

  • 업무 중심의 프론트엔드 개발 경험

    물류 업무에 필요한 기준정보 관리, 조건별 조회 및 실적 분석 화면을 개발하며 사용자의 업무 흐름을 고려한 UI 구성 경험을 쌓았습니다.

  • 대용량 데이터 처리 경험

    차량 약 1.4만 건과 기사 약 5천 건의 데이터 조회에 Server-side Pagination을 적용해 페이지 단위 조회 구조를 구현했습니다.

  • 프론트엔드와 API·DB 간 데이터 흐름 이해

    화면의 조회 조건부터 API 요청, SQL 집계, 결과 표시까지 이어지는 흐름을 살펴보며 데이터 처리 과정에서 발생하는 문제를 분석했습니다.

  • 데이터 시각화 및 분석 화면 개발

    월간 운송 실적과 컨테이너별 매출·비용을 확인할 수 있는 조회 기능을 구현해 사용자의 실적 분석 업무를 지원했습니다.

  • 문제 분석 및 개선 역량

    조회 지연과 집계 오류의 원인을 분석하고 SQL 및 데이터 조회 구조를 개선하며 화면의 사용성과 데이터 신뢰성을 함께 고려하는 경험을 쌓았습니다.
