FRONTEND DEVELOPMENT · SYSTEM MAINTENANCE

SCM / e-Accounting 시스템 운영 및 유지보수

2024.01 ~ 현재

실서비스의 구매·물류 및 회계 시스템을 유지보수하며 사용자 화면 개선, 업무 데이터 조회 및 상태 처리 오류 해결을 수행한 프로젝트입니다. 기존 시스템의 동작 흐름을 분석하고 업무 사용성을 높이는 데 중점을 두었습니다.

프로젝트 개요

Kolmar BNH의 핵심 업무 시스템인 공급망 관리 시스템(SCM)과 전자 회계 시스템(e-Accounting)의 기능 개선 및 운영 유지보수를 수행했습니다.

SCM에서는 발주 접수, 납품예정 등록, 납품 현황 조회, 입고실적 마감 등 구매·물류 업무 화면과 관련 데이터 집계 로직을 점검하고 오류를 개선했습니다.

e-Accounting에서는 법인카드, 세금계산서, 일반전표, 개인경비 등 다양한 전표 유형의 상신·결재·승인 기능을 유지보수하고, 상태 전환 및 일괄 처리 과정에서 발생하는 데이터 정합성 문제를 개선했습니다.

프론트엔드 관점에서는 업무 화면의 입력 및 조회 흐름, UI/UX 개선, 엑셀 다운로드 등 사용자 편의 기능과 화면에서 사용하는 데이터 처리 로직을 중점적으로 다뤘습니다.

담당 업무

기존 업무 화면과 데이터 처리 흐름을 분석하고, 사용자가 업무를 안정적으로 수행할 수 있도록 기능을 개선했습니다.

  • 업무 화면 UI/UX 개선

    전표 유형별 생성 화면과 조회 화면의 사용성을 개선하고, 엑셀 다운로드 등 업무 편의 기능을 보완했습니다.

  • 발주·납품 데이터 조회 개선

    발주 접수, 납품예정 등록 및 시간대별·마감 기준 납품 현황 조회 로직을 점검하고 개선했습니다.

  • 검색 결과 및 집계 데이터 정합성 개선

    구매 잔여 수량과 납품 실적 집계 SQL을 검토해 화면에 표시되는 데이터의 불일치 문제를 조치했습니다.

  • 전표 상신·결재 화면 기능 유지보수

    전표 유형별 처리 흐름과 결재 상태 표시 관련 오류를 분석하고, 일괄 상신 및 승인 기능의 처리 로직을 보완했습니다.

  • 화면과 서버 간 데이터 처리 점검

    업무 요청에 따른 데이터 처리 흐름을 확인하고, 상태값 갱신 및 예외 상황에서 발생하는 문제를 개선했습니다.

  • 운영 이슈 대응 및 레거시 코드 개선

    기존 코드의 동작 구조를 분석하고 운영 중 발생한 오류를 수정해 업무 기능의 안정성을 높였습니다.

주요 구현 및 개선 기능

01 · SCM

발주 및 납품 관리 화면

발주 접수부터 납품예정 등록, 납품 현황 확인까지 구매·물류 담당자가 사용하는 업무 흐름을 지원하는 기능을 유지보수했습니다.

  • 발주 미접수 건 필터링 및 발주 알림 로직 개선
  • 납품예정 등록 및 고객사 전송 후 상태값 갱신 오류 수정
  • 발주서별·시간대별 납품 현황 집계 및 차트 표시 로직 개선
  • 구매 잔여 수량 산출 SQL을 보완해 조회 데이터 정합성 개선
  • 마감 기준에 맞는 납품 실적 조회 및 집계 처리 점검
02 · E-ACCOUNTING

전표 생성 및 일괄 상신

다양한 유형의 전표를 생성하고 결재로 전달하는 업무 화면과 데이터 처리 로직을 개선했습니다.

  • 전표 유형별 생성 화면의 UI/UX 및 예외 처리 개선
  • 다건 전표 일괄 상신 시 데이터 처리 흐름 점검
  • 전표 그룹 상신 과정의 트랜잭션 및 오류 처리 보완
  • 세금계산서 및 일반전표의 후속 증빙 연계 기능 개선
03 · E-ACCOUNTING

다단계 결재 및 승인 상태 관리

부서 결재부터 회계 담당자 및 팀장 승인까지 이어지는 전표 처리 흐름을 점검하고 상태 전환 관련 문제를 개선했습니다.

  • 부서 결재 후 승인 대기 목록에 전표가 표시되지 않는 문제 해결
  • 전표 유형별 결재 상태 전환 로직의 누락된 처리 케이스 보완
  • 일괄 승인 및 반려 처리 과정의 예외 처리 개선
  • 전표 현황 조회 및 엑셀 다운로드 기능 유지보수

트러블 슈팅

ISSUE 01 · SCM

납품 현황 집계 데이터 불일치

마감 기준 납품 현황 화면의 수치와 납품예정 등록 수량이 일치하지 않고, 일부 데이터가 중복 집계되는 문제를 해결했습니다.

문제 원인

  • GROUP BY 집계 쿼리에서 고객사 전송 상태에 따른 조건 분기가 누락됨
  • 전송 후 DB 상태값이 정상적으로 반영되지 않아 동일 건이 중복 집계됨

개선 작업

  • 전송 상태에 따른 조건 분기를 보완하고 NVL 처리를 통해 NULL 집계 문제 수정
  • 전송 완료 후 상태값이 정상 반영되도록 트랜잭션 처리 흐름 보완
  • 집계 쿼리와 상태값 갱신 과정을 함께 점검해 중복 집계 원인 개선

개선 결과

미전송·전송 데이터의 집계 조건을 명확히 하고 상태값 갱신 문제를 개선해 납품 현황 조회와 마감 데이터의 정합성을 높였습니다.

ISSUE 02 · E-ACCOUNTING

전표 결재 상태 누락 및 일괄 처리 오류

부서 결재 후 승인 화면에서 전표가 누락되거나, 일괄 상신 중 일부 전표의 상태값이 정상적으로 갱신되지 않는 문제가 발생했습니다.

문제 원인

  • 특정 전표 유형의 단계별 상태 전환 처리 분기가 누락됨
  • 일괄 상신 중 일부 항목에서 오류가 발생했을 때 예외 및 트랜잭션 처리가 미흡함

개선 작업

  • 전표 유형별 상태 전환 분기를 점검하고 누락된 처리 케이스 보완
  • 일괄 상신 과정의 예외 처리와 트랜잭션 롤백 로직 개선
  • 결재 단계별 상태값과 승인 대기 목록의 조회 조건 점검

개선 결과

결재 상태 누락과 일괄 처리 오류를 개선해 승인 대기 목록의 조회 정확성과 회계 결재 프로세스의 안정성을 높였습니다.

프로젝트 성과 및 배운 점

  • 실서비스 UI 유지보수 경험

    기존 화면과 업무 흐름을 분석하고, 사용자 요청에 맞춰 입력·조회 인터페이스와 편의 기능을 개선했습니다.

  • 화면 데이터 정합성 개선

    조회 SQL과 상태값 갱신 과정을 함께 점검해 화면에 표시되는 데이터의 불일치와 중복 집계 문제를 해결했습니다.

  • 복잡한 업무 상태 처리 이해

    전표 유형별 결재 단계와 상태 전환 로직을 분석하며 화면의 표시 상태와 서버 데이터 간 일관성을 고려하는 경험을 쌓았습니다.

  • 운영 이슈 분석 및 문제 해결

    레거시 시스템의 기존 동작을 파악하고, 오류 원인 분석부터 수정 및 검증까지 운영 환경에서 문제를 해결했습니다.

  • 프론트엔드와 데이터 처리 흐름에 대한 이해

    UI 변경뿐 아니라 API 요청, 데이터 조회, 상태 갱신까지 연결된 흐름을 살펴보며 사용자 화면의 신뢰성과 업무 사용성을 함께 고려했습니다.
