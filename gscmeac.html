SCM / e-Accounting 시스템 운영 및 유지보수

2024.01 ~ 현재

구매·물류 및 회계 업무 시스템의 화면 개선 · 데이터 정합성 검증 · 운영 이슈 해결

프로젝트 개요

Kolmar BNH의 공급망 관리 시스템(SCM)과 전자 회계 시스템(e-Accounting)의 기능 개선 및 운영 유지보수를 수행했습니다. 기존 시스템의 업무 흐름과 데이터 처리 구조를 분석하고, 사용자 화면의 편의성과 업무 데이터의 정확성을 개선했습니다.

SCM · 공급망 관리

발주 접수, 납품예정 등록, 납품 현황 조회, 입고실적 마감 등 구매·물류 업무 화면을 유지보수하고, 납품 수량 집계 및 상태값 갱신 과정에서 발생하는 오류를 개선했습니다.

e-Accounting · 전자 회계

법인카드, 세금계산서, 일반전표, 개인경비 등 전표 유형별 생성·상신·결재 기능을 유지보수하고, 결재 상태 전환과 일괄 처리 과정에서 발생하는 데이터 정합성 문제를 개선했습니다.

주요 개발 방향

업무 화면의 입력 및 조회 흐름, UI/UX, 엑셀 다운로드 기능을 개선하고, 화면과 서버 간 데이터 전달 및 상태값 처리 과정을 점검해 실서비스의 안정적인 운영을 지원했습니다.

기술 스택

Nexacro N Java Spring Framework REST API MyBatis Oracle GitLab

담당 업무

  • 업무 화면 UI/UX 개선: 전표 유형별 생성 및 조회 화면을 개선하고 엑셀 다운로드 등 업무 편의 기능 보완
  • 발주·납품 데이터 조회: 발주 접수, 납품예정 등록, 시간대별 납품 현황 및 마감 기준 조회 로직 점검
  • 조회 및 집계 데이터 정합성 개선: 구매 잔여 수량과 납품 실적 집계 SQL을 검토하고 데이터 불일치 문제 해결
  • 전표 상신·결재 기능 유지보수: 전표 유형별 처리 흐름과 결재 상태 표시 오류를 분석하고 일괄 상신 및 승인 로직 보완
  • 화면·서버 데이터 처리 점검: API 요청부터 데이터 갱신까지의 흐름을 확인하고 상태값 및 예외 처리 문제 개선
  • 운영 이슈 대응: 기존 코드의 동작 구조를 분석하고 운영 중 발생한 오류를 수정해 업무 기능의 안정성 향상

주요 구현 및 개선 기능

1. SCM 발주 및 납품 관리

발주 접수부터 납품예정 등록, 납품 현황 확인까지 구매·물류 담당자의 업무 흐름을 지원하는 화면과 데이터 처리 기능을 유지보수했습니다.

  • 발주 미접수 건 필터링 및 발주 알림 로직 개선
  • 납품예정 등록 및 고객사 전송 후 상태값 갱신 오류 수정
  • 발주서별·시간대별 납품 현황 집계 및 차트 표시 로직 개선
  • 구매 잔여 수량 산출 SQL을 보완해 조회 데이터 정합성 개선
  • 마감 기준에 따른 납품 실적 조회 및 집계 처리 점검

2. e-Accounting 전표 생성 및 일괄 상신

다양한 유형의 전표를 생성하고 결재 단계로 전달하는 업무 화면과 관련 데이터 처리 흐름을 점검하고 개선했습니다.

  • 전표 유형별 생성 화면의 UI/UX 및 예외 처리 개선
  • 다건 전표 일괄 상신 시 데이터 처리 흐름 점검
  • 전표 그룹 상신 과정의 트랜잭션 및 오류 처리 보완
  • 세금계산서 및 일반전표의 후속 증빙 연계 기능 개선

3. e-Accounting 다단계 결재 및 승인 상태 관리

부서 결재부터 회계 담당자 및 팀장 승인까지 이어지는 전표 처리 흐름을 점검하고 상태 전환 관련 문제를 개선했습니다.

  • 부서 결재 후 승인 대기 목록에 전표가 표시되지 않는 문제 해결
  • 전표 유형별 결재 상태 전환 로직의 누락된 처리 케이스 보완
  • 일괄 승인 및 반려 처리 과정의 예외 처리 개선
  • 전표 현황 조회 및 엑셀 다운로드 기능 유지보수

트러블 슈팅 (Problem Solving)

1. SCM 납품 현황 집계 데이터 불일치

문제 및 원인

마감 기준 납품 현황의 수치와 납품예정 등록 수량이 일치하지 않고 일부 데이터가 중복 집계되는 문제가 발생했습니다. 집계 SQL의 고객사 전송 상태별 조건 분기와 전송 후 DB 상태값 갱신 과정에 원인이 있었습니다.

해결 과정

  • GROUP BY 집계 쿼리의 고객사 전송 상태별 조건 분기 점검 및 보완
  • NVL 처리를 적용해 NULL 값으로 인한 집계 예외 수정
  • 고객사 전송 이후 상태값 갱신 및 트랜잭션 처리 흐름 점검
  • 집계 SQL과 상태값 갱신 결과를 함께 확인해 중복 집계 원인 개선

개선 결과

전송 상태별 집계 조건과 상태값 갱신 과정을 보완해 납품 현황 조회 결과의 정확성과 마감 데이터의 정합성을 개선했습니다.

2. e-Accounting 전표 결재 상태 누락 및 일괄 처리 오류

문제 및 원인

부서 결재 후 승인 화면에서 전표가 누락되거나, 일괄 상신 중 일부 전표의 상태값이 정상적으로 갱신되지 않는 문제가 발생했습니다. 전표 유형별 상태 전환 분기와 예외 상황의 처리 방식이 주요 점검 대상이었습니다.

해결 과정

  • 전표 유형별 결재 단계 및 상태 전환 분기를 점검하고 누락된 처리 케이스 보완
  • 일괄 상신 과정의 예외 처리와 트랜잭션 롤백 로직 점검 및 개선
  • 결재 단계별 상태값과 승인 대기 목록의 조회 조건 확인
  • 일괄 승인 및 반려 처리 후 데이터 상태가 정상 반영되는지 검증

개선 결과

결재 상태 누락과 일괄 처리 예외를 보완해 승인 대기 목록의 조회 정확성과 회계 결재 프로세스의 안정성을 개선했습니다.

프로젝트 성과 및 기술 역량

  • 실서비스 화면 개선: 기존 업무 화면과 사용자 흐름을 분석해 입력·조회 UI 및 편의 기능 개선
  • 데이터 정합성 개선: SQL 집계 조건과 상태값 갱신 과정을 점검해 데이터 불일치 및 중복 집계 문제 해결
  • 업무 프로세스 이해: 발주·납품 처리와 전표 유형별 결재 단계 및 상태 전환 흐름에 대한 이해 확보
  • 운영 이슈 분석 및 해결: 레거시 코드의 기존 동작을 파악하고 원인 분석부터 수정 및 검증까지 수행
  • 프론트엔드와 데이터 흐름 이해: 사용자 화면, API 요청, 조회 결과 및 상태값 갱신 간 연관성을 고려한 기능 개선 경험 축적
